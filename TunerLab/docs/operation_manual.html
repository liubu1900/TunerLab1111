0. 文档说明

本手册面向 TunerLab Web 控制台（命令 python -m tuner.web），即把原来的 PySide6 桌面界面改造成的浏览器界面。所有硬件驱动与校准逻辑均复用原有代码，仅表现层换成了网页。

  • 硬件驱动（Zmotion 四轴、多厂商矢网）运行在连接着仪器的 Windows 主机上的本地 Web 服务里；浏览器通过 http://127.0.0.1:8000 访问（同机或局域网内其他设备均可）。
  • 本手册中的图均为界面示意图（SVG 绘制），用于说明布局与流程，实际页面以软件运行为准。
  • 文档依据：tuner/vna_drivers.py、tuner/web/*、docs/VNA.md、docs/HARDWARE.md。

TunerLab 采用本地 Web 服务 + 浏览器的三层结构：

2. 环境准备与启动

2.1 运行环境

  • 操作系统：Windows（Zmotion DLL 仅 Windows 可用；Web 服务须跑在连着控制器的机器上）。
  • Python：3.13 或 3.14 均可；Web 控制台不需要 PySide6（桌面版才需要），仅用标准库。
  • 浏览器：任意现代浏览器（Chrome / Edge / Firefox）。
  • 依赖：numpy、scipy、h5py 用于校准数学；矢网与 Web 服务本身零额外依赖。

2.2 启动方式一：双击 run.bat（推荐）

直接双击工程根目录的 run.bat，会弹出菜单：

# 菜单示例
  TunerLab 启动菜单
  1  运动控制台      (tuner.app  - 实机四轴)
  2  校准工作台      (tuner.ui   - Mock 数据)
  3  Web 控制台      (tuner.web  - 浏览器)
  0  退出
  请选择 [1/2/3/0]: 3

输入 3 回车，程序自动启动 Web 服务并打开浏览器到 http://127.0.0.1:8000。说明run.bat 用 cd /d "%~dp0" 自动切到脚本目录，无需手敲中文路径。

2.3 启动方式二：命令行

4. 运动控制台（3 轴 / 4 轴 tuner 型号）

运动控制台含三个页面，对应你最初的需求：通讯设置、移动控制、每轴参数设定。全部复用真实 Zmotion 驱动。

图 3  运动控制台三页：① 通讯设置 ② 轴移动控制（含标度自检 / 急停 / 复位）③ 轴参数设定

4.1 通讯设置

  • 填控制器 IP（默认 192.168.0.11），点 连接（失败自动重试 3 次）；可点 搜索 触发 UDP 广播发现。
  • 连接后会显示固件版本、SDK 路径；通讯参数（IP 等）以 JSON 文件持久化，下次启动自动载入，并支持导入/导出。
  • tuner 型号：选择本机是 3 轴还是 4 轴机型（见 4.2）。

4.2 tuner 型号（3 轴 / 4 轴）

软件同时支持两种 tuner 型号，在通讯设置 › tuner 型号 下拉切换，选择结果 持久化在设置文件里，下次启动自动沿用。

型号轴探针数校准网格点数
3 轴X / Z1 / Z22x_count × z_count²
4 轴X / Z1 / Z2 / Z33x_count × z_count³
关键约定：控制器的物理轴序号固定不变（X=0、Z1=1、Z2=2、Z3=3）。 切换型号只改变"软件命令哪几根轴"，不影响已保存的校准数据与轴参数—— 两种型号间可以直接切换，改回去也不用重新标定。
  • 切换后，轴移动控制与轴参数设定的表格行数、轴下拉自动增减（3 轴机型不再出现 Z3）。
  • 离开型号的轴，其参数仍然保留在设置文件里，切回型号即可复用（含已修正的 UNITS）。
  • 实机校准时探针数由型号决定，不能手工选成与机器不符的探针数——否则标定网格会 去访问不存在的轴。
  • 3 轴机型的网格点数是 4 轴的 1/z_count 倍（z_count=4 时约 1/4）， 标定更快，但覆盖度也更低；可用 6.3 的 Smith 图细化布点补齐。

4.3 真实 / 虚拟模式

运动控制台可在真实控制器（Zmotion 运动控制卡）与虚拟控制器（内置模拟器） 之间切换。选择在通讯设置 › 控制器模式里完成，并持久化到设置文件。

项目真实模式虚拟模式
需要硬件是否
通讯方式UDP 广播发现实机无（virtual://zmotion）
初始状态读取实机位置与回零状态自动回零并生成初始位置
标度自检实测编码器比例默认一致（可注入故障模拟偏差）
故障演练不可可注入状态位
虚拟校准数据不可一键生成合成校准库
切换模式会断开当前连接——两种后端没有共同点， 半连接状态最危险。切到虚拟模式时 IP 输入框自动置灰（虚拟模式不需要 IP）。

虚拟模式的两项演练工具

  • 虚拟故障演练（仅虚拟模式可见）：向指定轴注入状态位，用来练习读取与判读诊断页。 默认 bit22 = 告警信号输入，正是实机 Z2 曾出现的那一位 （状态字 4194304）。注入后该轴在状态表中标红。
  • 生成虚拟校准数据（仅虚拟模式可见）：一键生成含各点位 S 参数的合成校准库， 结构与实测库完全一致（含 provenance 标记），可直接用于 Smith 图、阻抗调谐与插值验证。 点数 = X 层数 × Z 层数^探针数。

4.4 轴移动控制

  • 选轴后可用 点动 +/−、绝对定位、回零、停止。
  • 标度自检（关键）：软件对当前轴做小幅往返，用编码器反馈实测"指令位移 / 反馈位移"的真实比例，存入 feedback_scale。标度不匹配时软件默认拒绝该轴运动（安全行为）。首次实机务必先点它。
  • 采纳并写入修正后的 UNITS：标度不一致时，自检结果会给出修正值 UNITS_修正 = 当前 UNITS ÷ 实测比值（例如 UNITS=10000、比值 84 → 约 119）。 点该按钮即把修正值写入控制器并保存到设置文件，同时把该轴的 feedback_scale 归 1。
    注意：UNITS 决定"一个指令单位等于多少毫米"，改写后坐标系随之改变， 该轴必须重新回零。软件会自动把该轴标记为未回零。
  • 急停 / 复位：软件急停锁存，可软件复位；但不能替代硬件急停 / 限位。
  • 状态区每 300 ms 刷新位置、速度、回零状态、报警位。

4.5 轴参数设定

  • 可读取 / 写入每轴 ATYPE / UNITS / SPEED / ACCEL / DECEL / CREEP / JOG_SPEED / DATUM_IN 等，以及实测的 feedback_scale。
  • 点 保存 写入设置文件，供后续启动调用。

4.6 每轴状态与控制器报错

「轴移动控制」页的状态表每 300 ms 刷新一次，除位置外还给出控制器自己的报错：

列来源含义
AXISSTATUS控制器轴状态字位域，置位即表示该轴有对应状态
状态说明软件解码把状态位翻译成中文，例如「告警信号输入 (bit22)」
停止原因AXIS_STOPREASON锁存的最后一次停止原因，鼠标悬停可见十六进制原值

厂商文档中常用的状态位（软件已内置完整表，未定义位也会显式报出）：

位打印值说明性质
bit38远程驱动器报错故障
bit4 / bit516 / 32正向 / 反向硬限位触发故障
bit664找原点中活动
bit8256随动误差超限出错故障
bit9 / bit10512 / 1024超过正向 / 负向软限位故障
bit112048CANCEL 执行中活动
bit224194304告警信号输入故障
bit238388608轴进入了暂停状态故障
两个按钮：
· 读取控制器错误码：通过 Basic 通道向控制器索取它自己的错误号并翻译成文字， 同时汇总哪些轴处于报警状态。该查询只在点击时发出，不进入 300 ms 轮询—— 因为一条不被固件支持的指令本身就会在控制器上产生错误，反而污染状态。
· 刷新详细状态：额外读取每轴使能状态与实测速度。
参考：此前 Z2 的 AXISSTATUS=4194304 即 bit22 告警信号输入， STOP_REASON=4196352 = bit22 + bit11（CANCEL 执行中）。该故障已由现场修复， 修复后本表应显示「正常」。

4.7 操作日志

左侧导航 运行记录 → 操作日志。记录所有操作，每条含时间、分类、动作、详情、级别：

  • 分类：通讯 / 运动 / 回零 / 参数 / 急停 / 标度 / 矢网 / 校准 / 系统
  • 级别：info / warn / error（错误行红底、警告行黄底）
  • 动作内容：绝对定位目标、点动增量、回零状态码、标度自检比值、急停、参数写入、校准布点与覆盖度等
  • 失败的操作会连同异常类型与消息一起记录（如 MotionError: ...）

内存保留最近 2000 条；支持按分类/级别过滤、清空、导出 JSON。桌面版运动控制台也有同名页面（第 4 页）。

日志是排查"到底下发了什么指令、控制器回了什么"的依据：实机异常时先看这一页。

6. 校准工作台

校准工作台是一套阻抗调谐 / 校准流程（Smith 图、阻抗搜索、RF 验证）。默认使用 Mock 合成数据， 也可勾选"使用真实矢网"接入实机采集。

6.1 用真实矢网跑校准

  • 导航 → 校准工作台（模拟）→ Dashboard。
  • 勾选 使用真实矢网 (TCP/IP)，填厂商 / IP / 起始 / 终止 / 频点。
  • 点 初始化模拟硬件并回零。注意：运动控制器（Zmotion）与矢网相互独立；真实矢网只替换"测量"这一环，S 参数来自实机。
  • 后续「校准设置 / 校准运行 / 数据库 / Smith 图 / 阻抗调谐 / 验证报告」流程不变。
单台矢网二选一：若同一台矢网同时被"VNA 面板"和"校准工作台真实矢网"占用，命令会交错。 建议要么在 VNA 面板手动采，要么进校准工作台让它托管，不要同时操作。

6.2 校准流程

6.3 Smith 图均匀布点

旧版用笛卡尔机械网格布点：X 取 x_count 个值、每个 Z 轴取 z_count 个值， 点数 = x_count × z_count^probes（3 探针默认 576 点），而且大量点落在 Smith 图的 Γ 死区。

新方案按行业通用做法把标定点铺在阻抗平面上：点数与探针数无关，密度分档 Low 95 / Medium 181 / High 361（与通用分档一致）。

布点方式说明
笛卡尔网格旧方式，保留以兼容既有校准库
Smith 图均匀布点 把均匀目标点集反解为机械坐标。需要先有一轮已测点建立响应模型， 没有实测数据时软件会明确提示"请先用笛卡尔网格建库并运行"
分布方式 Sunflower 螺旋（默认）：Fermat 螺旋，181 点时最近邻间距变化 < 2%，最均匀；
同心环：等面积环、奇偶交错，便于在图上对应"相位层"
|Γ| 上下限限制布点的反射系数范围，默认 0 ~ 0.95

推荐工作流

  1. 先用笛卡尔网格建库并跑一轮（点少、快），得到一批已测点。
  2. 点 预览布点与覆盖度：画布上蓝点是目标点集、红点是已测点， 下方显示已测点的平均/最大间距与覆盖率。
  3. 点 Smith 图细化布点（补点）：软件用已测点拟合出调谐器响应模型， 在 Γ 平面上挑出离已有数据最远的点作为补充点，追加进同一个校准库（原子写入，不破坏历史）。
  4. 回到「校准运行」继续测新点，覆盖度随之提高；重复 2~3 轮即可逼近均匀覆盖。
为什么是"两段式"而不是一次到位：调谐器从探针深度到 |Γ| 的映射取决于探针几何与夹具， 任何先验模型都可能带偏整个布点。因此软件从实测中学习响应，再据此安排下一批点位—— 这与"均匀布点 + 二阶插值"、"按应用自动选表征方法"的通用思路一致。

6.4 实机校准工作流

校准工作台的运动来源可切换：模拟运动（Mock，无硬件）或 实机 Zmotion（四轴 X / Z1 / Z2 / Z3）。 实机模式复用「通讯设置」里那条控制器连接，不会第二次打开控制器。

安全闸门（软件强制）：实机模式下，如果任一轴的 feedback_scale ≠ 1 （即 UNITS 与反馈标度仍不一致），初始化会被直接拒绝，并提示先做标度自检。 原因很实在：UNITS 差 84 倍，校准网格的"10 mm"就会让机器实际走 840 mm。

照着做的顺序

  1. 通讯设置页：填 192.168.0.11 → 点「连接」。状态表四轴「状态说明」应全为正常。
  2. 轴移动控制页：选轴 → 点「标度自检」（步长 0.005，会自动回原位）。 记录比值与软件给出的修正后 UNITS。
  3. 点「采纳并写入修正后的 UNITS」→ 控制器与设置文件同步更新。 该轴此后必须重新回零（软件已把它标记为未回零）。四轴都做一遍。
  4. 校准工作台 → Dashboard：运动来源选实机 Zmotion，填行程 （X 起点/终点、Z 起点/终点、安全 Z），点「回零（实机）」。 提示回零会移动机器，是独立的显式动作，初始化不会自动回零。
  5. 回零成功后点「初始化」→ 通过标度闸门后建立校准库。
  6. 校准设置页：先用笛卡尔网格建库（点少、快）→ 校准运行跑一轮 → 回到校准设置点 「预览布点与覆盖度」→「Smith 图细化布点（补点）」→ 再跑一轮。重复 2~3 轮。
  7. Smith 图页看 Γ 分布，阻抗调谐页找目标阻抗，验证报告页看复现性。

行程参数怎么填

参数含义说明
X 行程起点/终点共享 X 轴允许走到的范围 (mm) 标定点只会在这个区间内；控制器出厂软限位仍是外层保护
Z 行程起点/终点三个探针轴的插入深度范围 (mm) 决定 Smith 图上可达的 |Γ| 范围
安全 Z探针完全回缩的位置 (mm) 共享 X 移动前，所有探针必须在这个位置
行程参数是校准的硬边界：软件用它们校验每一个标定点， 超出范围的位置根本不会被下发到机器。填之前请先用轴移动控制页点动， 确认各轴的实际可用范围与方向（正方向可能是负的）。

6.5 插值调谐（二阶 Lagrange + 两段式寻点）

「阻抗调谐」页现在有两种寻点能力：最近邻查表（旧版，只能给出已标定的点）与 插值调谐（在标定数据之上做连续推断）。

插值算法

标定数据形态使用的插值器说明
完整张量网格
（笛卡尔网格布点）		 二阶 Lagrange
（二阶 Lagrange 算法）		 逐轴三次（二阶）插值：幅度轴（探针深度）先插，相位轴（X 载物台）后插。 2 维即经典的 9 点邻域，n 维为 3ⁿ 点
散点
（Smith 图细化布点）		 局部二次拟合 取邻近点做加权二次最小二乘；邻域不足时自动降到一次或最近点

两种插值器都插值四个 S 参数（不是 Γ），再按端口约定与夹具换算成 Γ—— 这正是二阶 Lagrange 插值的标准做法。

两段式寻点

  1. 一般搜索：在 Γ 平面上找最近的已标定点，作为起点。
  2. 梯度搜索：在插值模型上做局部寻优（最小化 |Γ(x) − Γ_target|）。
  3. 细网格修正：在结果附近加密采样再取最优（细网格 fine interpolation grid）。

页面上的阶段表会显示每一阶段的误差矢量，能直接看出每一步的贡献。

实测效果（Mock 调谐器，7×3×3 = 63 点网格，目标 Z=30 Ω）：
最近邻查表 |ΔΓ| = 1.02e-01（约 −20 dB，即未做细网格插值时的典型水平）
梯度搜索后 |ΔΓ| = 1.54e-08 —— 提升约 7 个数量级。
注意：这是模型内的收敛度；模型本身对真实机器的偏差取决于标定密度，必须实测复核。

怎么选

调谐算法用途
两段式（默认）生产使用：给出连续点位，精度最高
梯度搜索跳过细网格，节省一点时间
一般搜索只要"最近的已标定点"时用
最近邻查表旧版行为，保留作对照
插值层级策略：默认「最近三层」——选取中心最接近查询值的三层， 查询被夹在中间时是内插而非外推，数值最稳。另一选项「原始规则」按经典取层方式 下 1 层 + 上 2 层，属另一种偏置策略。

标定密度决定精度上限

插值误差主要来自相邻两层之间的相位跨度。X 载物台每走一格，反射相位转多少度， 就是插值的"难度"。软件给出经验建议：

相位跨度每格相位步长上限建议 X 层数
360°20°19
360°45°9

实测：网格加密一倍，插值误差下降到约 1/4（二阶收敛）。所以 X 层数别省—— 这是提升调谐精度最有效的一个旋钮，比换算法更管用。

注意：调谐结果是模型预测。移动到该位置后， 请用「验证当前阻抗」实测复核，模型与真实机器的偏差要以实测为准。

6.6 插值验证闭环

「验证报告」页新增插值验证闭环，做法与行业通用方法一致： 把调谐器移到一组插值得到的阻抗点（网格单元中心，不是标定点本身）， 用已校准的仪器实测，与模型预测比较误差矢量；超过容差即建议重新标定。

这一步会移动机器，且耗时与验证点数成正比。

验证点怎么选

策略说明
覆盖最难处（默认） 挑 Γ 平面上离已标定点最远的位置——插值最容易出错的地方，验证信息量最大
均匀分散在整个候选集上均匀取点，做一般性检查

误差矢量的三种读法

分量含义指向的问题
|ΔΓ|Γ 平面上的矢量距离（误差矢量 error vector）总体偏离
幅度分量反射系数幅值差探针深度/增益不对、标定点太稀
相位分量反射系数相位差（换算到 Γ 平面距离）X 相位层数不足、载物台行程标度不对

报告会指出哪一项占主导，并给出排查方向——这比只给一个总误差有用得多。

实测示例

用 Mock 调谐器、7×3×3 = 63 点网格、4 个验证点跑出来：
判定 = 建议重新标定，最大 |ΔΓ| = 0.088140（−21.1 dB）
误差以幅度分量为主（幅度 0.0755 vs 相位 0.0033）
→ 结论：标定点太稀，不是标度问题。加密 Z 层数后重跑即可。
怎么用这个闭环：标定完成后跑一次验证。若判定"建议重新标定"， 看报告指出的主导分量——幅度主导就加密 Z 层数，相位主导就加密 X 层数（见 6.5 的相位跨度表）。 反复几轮，直到判定为"通过"，这套标定才真正可以用于生产调谐。

8. 常见问题 FAQ

Q1：python -m tuner.web 启动后浏览器没自动打开？

手动访问 http://127.0.0.1:8000；或用 --no-browser 后自行打开。若端口被占，加 --port 8001。

Q2：连接 Zmotion 失败？

它是 UDP 广播发现，先确认上位机与控制器同网段（192.168.0.x），不要查 TCP 端口；可点「搜索」再连。

Q3：矢网连不上？

先用 ping 和 Test-NetConnection -Port 5025 验端口；确认仪器已开 SCPI 服务器、防火墙放行 5025。

Q4：移动轴时报"标度不匹配"？

这是预期的安全行为。到「轴移动控制」点 标度自检，测出真实比例存盘后即可放行。

Q5：Z2 点不动？

此前 Z2 的 AXISSTATUS=4194304（bit22 告警信号输入）已由现场修复。 现在状态表会直接显示该轴的状态说明与停止原因；修复后应显示「正常」。 若再次出现 bit22，先看「读取控制器错误码」的输出与操作日志里该轴前后的动作。

Q6：操作日志存在哪里？

默认只在内存（最近 2000 条），重启即清空。需要留档就用操作日志页的 导出 JSON， 导出文件是完整记录（含时间戳、级别与结构化数据）。

Q7：Smith 图布点提示"需要先有一轮已测点"？

这是设计如此：调谐器从探针深度到 |Γ| 的映射取决于探针几何与夹具，软件不预设模型。 先用笛卡尔网格建库并跑一轮，再做细化布点即可。

Q8：实机模式初始化被拒，提示"必须先修正标度"？

说明该轴的 UNITS 与反馈标度仍不一致。UNITS 差几倍，校准网格就会让机器实际走几倍的距离， 所以软件直接拒绝。到「轴移动控制」做标度自检，采纳修正后的 UNITS，再重新初始化。

Q9：改了 UNITS 之后还能直接运动吗？

不能。UNITS 决定"一个指令单位等于多少毫米"，改写后坐标系随之改变。 软件已把该轴标记为未回零，必须重新回零才能运动。

Q10：3 轴和 4 轴 tuner 怎么切换？会不会弄丢已标定的数据？

在通讯设置 › tuner 型号里切换，选择会保存到设置文件。 不会丢数据：控制器的物理轴序号是固定的，切换只改变软件命令哪几根轴， 已有的校准库（HDF5）和轴参数都照常可用。切换后各页面的轴表格会自动增减， 离开型号的轴其参数仍保留在文件里，切回即复用。

Q11：3 轴机型的标定点数是不是变少了？

是。笛卡尔网格点数是 x_count × z_count^探针数： 3 轴（2 探针）为 x_count × z_count²， 4 轴（3 探针）为 x_count × z_count³。 z_count=4 时 3 轴机型只有 4 轴机型约 1/4 的点数，标定更快但 Γ 覆盖更稀， 建议配合 6.3 的 Smith 图细化布点补齐。

Q12：没有硬件时怎么练操作流程？

在通讯设置 › 控制器模式里选虚拟控制器，点「连接」即可。 虚拟控制器会自动回零并生成初始位置，点动、回零、标度自检、急停、每轴状态与报错 全部照常工作。还可以注入状态位练诊断页，或一键生成合成校准数据练 Smith 图与调谐。 切回真实模式时连接会自动断开。
