# 实机首批校准操作清单：切真实源 → 建库 → 采第一批点

> 适用：`TunerLab 0.3.7`（各轴独立运动 + 单频点校准版）· 现场 4 轴机型 `X/Z1/Z2/Z3` · 2026-11-08  
> 目标：**第一次**用真实控制器 + 真实矢网建一个校准库并采少量点，验证整条链路，不追求库规模。  
> 本文按界面实际按钮与字段编写；字段默认值来自 `pages_studio.py`，门禁来自 `studio_bridge.py` / `web/handlers.py`。

| # | 检查项  | 在哪看               | 期望                                                                      |
| - | ---- | ----------------- | ----------------------------------------------------------------------- |
| 1 | 应用版本 | 标题栏 / `--version` | `TunerLab 0.3.7`（0.3.6 及更早**不支持单频点校准**，频点最小只能填 2）                        |
| 2 | 控制器  | 顶栏徽标 / 通讯设置页      | 绿点 `控制器 192.168.0.11`，固件 `2.9600`，模式「真实控制 (Zmotion)」                    |
| 3 | 机型   | 通讯设置页             | `4 Tuner (X, Z1, Z2, Z3)`                                               |
| 4 | 四轴回零 | 轴移动控制页 → 实时状态表    | 四行都是「已回零」，`AXISSTATUS=0`，状态/停止原因「正常」，空闲「是」                              |
| 5 | 标度   | 轴移动控制页 → 每轴「标度自检」 | 四轴比值都接近 1 且判「一致」，`UNITS` 正确（X 2500、Z 10000 脉冲/mm）                       |
| 6 | 软限位  | 轴移动控制页底部「申报行程」    | `X 0–403 · Z1/Z2/Z3 0–17 mm`；设置文件里 `feedback_scale=100`                 |
| 7 | 矢网   | 顶栏徽标 / 矢网控制页      | 绿点 `矢网 192.168.2.111`；IDN `Rohde&Schwarz,ZNA26-2Port,133400022`；最近错误「—」 |
| 8 | 机械安全 | 现场目视              | **探针已抬离 DUT**；硬件急停回路可用；X 横移路径上无遮挡                                       |

> ⚠️ **0.3.5 起软件不再阻止「探针伸入时动 X」**，且校准采集会把 X 与 Z **一次同时下发**。

> 需要的话重连后点一次「单次扫描」即可复现；它不影响本清单，因为校准会重新逐点采集。

## 1. 切真实源（左侧导航 →「布点与设置」）

按下面逐项设置。**带 ★ 的是默认值不对、必须手改的项**。

| 字段               | 设为                                                  | 说明                                           |
| ---------------- | --------------------------------------------------- | -------------------------------------------- |
| 运动来源             | `实机运动（Zmotion 控制器）`                                 | 选中后「申报行程」几个框才会解锁                             |
| 模拟探针数            | 灰掉，不用管                                              | real 时自动取机型，4 轴 = 3 探针                       |
| ★ 申报行程 X 下限 / 上限 | `0` / `2` （mm）                                      | 默认 `0–10`；**首批故意用小行程**，别一上来跑满 403 mm         |
| ★ 申报行程 Z 下限 / 上限 | `0` / `2` （mm）                                      | 默认 `0–1`；三个 Z 轴共用                            |
| 安全 Z             | `0` （mm）                                            | 探针收回位，默认取 Z 下限。**必须现场确认 0 mm 确实是抬离 DUT 的位置** |
| 矢网来源             | `真实矢网 (TCP/IP)`                                     | 选中后矢网参数才解锁                                   |
| 厂商               | `自动识别` 或 `Rohde & Schwarz (ZNB/ZVA/ZND)`            | 现场 IDN 含 `ROHDE`，自动识别会落到 `rsp` 命令集；显式选更稳     |
| ★ IP             | `192.168.2.111`                                     | **默认是 `192.168.0.50`，不改会连不上**                |
| 起始 / 终止 GHz      | 多频点 `1.0` / `20.0`；**单频点两个都填目标频率**，如 `10.0` / `10.0` | 见 §2.1；多点时必须 起始 < 终止     |
| ★ 频点               | 多频点 `401`；**单频点必须填 `1`**                         | 0.3.7 起最小值 1；0.3.6 及更早最小 2，无法单点        |
| 布点方式             | `笛卡尔网格（张量插值）`                                       | Smith 均匀布点需要「已有一轮已测点」，首轮不能用                  |
| ★ X 层数           | `3`                                                 | 默认 9                                         |
| ★ 每轴 Z 层数        | `2`                                                 | 默认 4；3 探针时点数 = `X × Z³`                      |
| 预计点数             | 应显示 `24 点（X 3 × Z 2^3）`                             | 默认组合会是 **576 点**，首批不要跑                       |
| 校准文件             | 保持默认 `Documents\TunerLab\calibrations\cal_<时间戳>.h5` | 每次新建自动带时间戳，不会覆盖旧库                            |

> 「申报行程」是**操作员声明的布点范围**，控制器里的 `FS/RS_LIMIT`（0–403 / 0–17 mm）仍是最外层软限位。  
> 两者不能颠倒：申报范围必须落在软限位之内，否则建库时点位校验会失败。

## 2. 建立校准库（同一页底部按钮「初始化并建立校准库」）

点一次即可，后台会依次做四件事（失败会弹窗告诉你卡在哪一步）：

1. `studio_bridge.init_hardware` 取运动页**已持有的那条控制器连接**（不会再开第二个句柄），  
   校验 `feedback_scale`（本机须为 `100` 或 `1.0`），用申报行程生成 `TunerConfig`；
2. 按矢网参数新建真实 VNA 连接并下发扫描设置（**会覆盖矢网页刚才设的频率/点数**）；
3. `studio_setup` 生成 24 个网格点位，创建 HDF5 + SQLite 边车，写入配置元数据；
4. 状态置为 `ready`。

**预期结果**

- 页面底部绿字：`已建立校准库：<路径> · 24 点`；
- 概览页：「运动来源 / 矢网来源」变为真实源，校准库显示新路径，有效点 `0 / 24`；
- 操作日志出现两条：`校准/初始化实机运动`（带行程与已回零轴列表）、`校准/建立校准库`；
- `Documents\TunerLab\calibrations\` 下多出 `cal_*.h5` 与同名 `.sqlite`。

### 常见报错对照

| 报错                                                | 原因                            | 处理                    |
| ------------------------------------------------- | ----------------------------- | --------------------- |
| `实机运动前必须先确认标度…与 MPOS 单位不符`                        | `feedback_scale` 不是 1.0 / 100 | 去「轴参数设定」核对，或先做一次标度自检  |
| `travel limits must be ordered and non-empty`     | 上下限填反或相等                      | 检查 X/Z 下限 < 上限        |
| 连接矢网超时 / `controller is not connected`            | IP 仍为 `192.168.0.50`，或运动页连接掉了 | 改 IP；回「通讯设置」重新连接控制器   |
| 矢网报「连接被占用」                                        | 矢网页与校准各开了一条 socket            | 先在「矢网控制」页点「断开」，再回来初始化 |
| `configuration differs from calibration database` | 库与当前配置不一致                     | 不要复用旧库，重新建一个带时间戳的新库   |
| `frequencies must be finite, positive and strictly increasing` | 起始 GHz = 终止 GHz 却填了 ≥2 个频点（`linspace` 生成一串相同频率） | **把频点改成 1**，或让 起始 < 终止；详见 §2.1 |

## 2.1 单频点校准（负载牵引最常用的工况）

只在一个频点（例如 **10 GHz**）建库调谐时，这样填：

| 字段 | 值 |
| --- | --- |
| 起始 GHz | `10.0000` |
| 终止 GHz | `10.0000`（可留任意值，0.3.7 会自动对齐到起始频率） |
| **频点** | **`1`** |

后端行为（`TCPVNA.set_sweep`）：向仪器下发 `STAR = STOP = 10 GHz`、`SWE:POIN 1`，
本地频率网格为 `[10e9]`；库里 `s` 的形状是 `(点数, 1, 2, 2)`，
调谐插值、Smith 图、验证报告都按单频点处理。部分矢网在 `STAR == STOP` 时仍会
返回 2 个以上 Trace 采样，驱动会只取第一个（都在同一频率）。

> **11-08 现场那次报错的根因**：起始 = 终止 = `10.0000` GHz、频点 `4`。
> 4 个点全是 10 GHz，`database.create()` 的「严格递增」校验不通过。
> 0.3.6 里频点最小只能填 2，所以「起止相等」必然失败；0.3.7 把它放开到 1，
> 并在**下发 SCPI 之前**用中文弹窗拦住「起止相等 + 多点」的组合。
>
> 若暂时不能升级：把起始 GHz 改成 `9.999`、终止 `10.000`、频点 `2`
> 可近似等效，但库里会有两个频点，不是真正的单点校准。

## 3. 采第一批点（左侧导航 →「采集运行」）

| 步骤 | 操作                            | 观察                                                |
| -- | ----------------------------- | ------------------------------------------------- |
| 1  | 确认状态 `ready`、进度 `0 / 24`      | 若显示 `idle`，说明第 2 步没成功，回去重建                        |
| 2  | 手放到急停按钮附近，点「**开始 / 继续**」      | 状态变 `running`，后台线程逐点执行                            |
| 3  | 每点：X/Z 一次到位 → 矢网按设定频点扫描（单点模式 1 点）→ 写库 | 进度递增；ASCII 取数约每点数秒，24 点预计数分钟              |
| 4  | 观察首个点的运动                      | **第一个点最关键**：确认探针不刮片、X 与 Z 同时下发时路径安全、无异常声响         |
| 5  | 异常时点「急停 EMERGENCY STOP」或「暂停」  | 急停会锁存，需「复位急停」并重新回零才能继续                            |
| 6  | 跑完                            | 状态 `completed`（或 `completed_with_errors`），库自动重新载入 |

> 支持断点续扫：中途「暂停」/「取消」后已测点仍保留在库里，回到 `ready` 后可「开始 / 继续」接着跑，  
> 不会重复覆盖有效点。别在 `running` 时去改行程、建新库或点手动运动——后端会拒绝（防止并发运动序列）。

## 4. 采后验收（别省这一步）

| 页面      | 看什么                  | 合格判据                                   |
| ------- | -------------------- | -------------------------------------- |
| 概览      | 有效点 / 总点             | `24 / 24`（或明确列出失败点）                    |
| 校准库     | 打开刚建的 `.h5`，看提交标记与来源 | `simulated=false`，来源隔离正常（模拟数据不会混写进真实库） |
| Smith 图 | 24 点的 Γ 分布           | 点分散、无大面积空洞；需要更均匀时用「Smith 图细化布点」补点      |
| 验证报告    | 插值误差 / A→B→A 重复性     | 误差矢量在可接受范围；重复性异常先查机械间隙与编码器             |
| 轴移动控制   | 四轴 `AXISSTATUS`      | 仍全 0、状态「正常」、无跟随误差累积                    |

**首批通过后再放量**：把申报行程逐步放大到接近软限位（`X 0–403`、`Z 0–17`），  
把网格从 `3 × 2³` 提到 `9 × 4³`（576 点）或更高。每次升规模前重跑一次标度自检。

## 6. 中断后的恢复与续扫（0.3.8 起）

采集页出现 `failed` 时**不要连点「开始 / 继续」**：第二次运行会把第一次的真实错误
文本覆盖成「故障已锁存」，丢失诊断信息。按下面顺序恢复：

| 步骤 | 位置 | 动作 |
| ---- | ---- | ---- |
| 1 | 采集运行页 | 记下错误文本与「点数 N / 总点数」（N 是 0 基最后成功索引，不是有效点数） |
| 2 | 轴移动控制页 | 点「**复位运动故障**」（`controller.reset_fault()`），再逐轴回零 X / Z1 / Z2 / Z3 |
| 3 | 轴移动控制页 | 确认四轴 `AXISSTATUS=0`、空闲、跟随误差 < 0.01 mm，探针已抬离 DUT |
| 4 | 布点与设置页 | 保持**与建库时完全相同**的参数（真实源、VNA IP、单点频率、行程、X/Z 网格数），把「校准文件」填成**原库路径** |
| 5 | 布点与设置页 | 点「初始化并建立校准库」；0.3.8 会识别已有库并显示「已加载校准库（续扫）… 已有 N / 总点数」 |
| 6 | 采集运行页 | 点「开始 / 继续」，从第一个 `valid=False` 的点续跑；已完成的点不会被覆盖 |
| 7 | 运行中 | 每点约 0.6–1 s，`点数` 递增、`valid` 与 SQLite `complete` 同步增长；最终 `576 / 576`、`pending=0` |

**参数不一致会直接报错**：频率网格不同 →「校准库的频率网格与当前矢网设置不一致」；
网格大小/行程不同 →「校准库的布点与当前网格不一致」。这时不要改旧库，另填一个新路径
重新建库。版本分叉与 `simulated` 来源隔离由 `CalibrationManager.run` 继续把关。

**0.3.7 及更早**：只能在同一进程内续扫（复位故障 + 回零 + 点继续）；一旦重启 exe，
旧库只能查看、不能续跑，只能新建库。升级到 0.3.8 后无此限制。

## 7. 在 Smith 图上点一个阻抗并实测验证（0.3.9 起）

这是「校准库 → 指定阻抗 → 到位实测」最短路径，不需要再手工换算 R / X。

| 步骤 | 位置 | 动作 |
| ---- | ---- | ---- |
| 1 | 通讯设置 / 布点与设置 | 连接控制器与矢网（0.3.9 起矢网 IP 默认已是实测可用的 `192.168.2.111`，`182.168.2.111` 不通）；**频率必须填成校准库的实际频点**（本次为 `5.000000 GHz`，默认 10 GHz 会显示"没有有效点"）；打开或续扫挂载原库 |
| 2 | Smith 图 | 点「刷新」，确认摘要显示「576 个实测点 · 5.0000 GHz」 |
| 3 | Smith 图 | 在**单位圆内**单击左键选择目标；右侧信息卡立刻显示 Γ、`\|Γ\|`/相位、Z (Ω)、归一化 z、VSWR、回波损耗、Γ/Smith 坐标 |
| 4 | Smith 图（可选） | 点「搜索对应点位」，查看 X\|Z1\|Z2\|Z3 机械位置、预测 Γ/Z 与 `\|ΔΓ\|`，确认点位可达 |
| 5 | Smith 图 | 设好容差（默认 `0.05`），点「**移动并实测验证**」；按钮禁用期间四轴正在运动，勿在别的上位机点动同一根轴 |
| 6 | Smith 图 | 「到位实测判定」给出目标 vs 实测的 Z / Γ / `\|Γ\|` / VSWR，`\|ΔΓ\|` 与容差结论、ΔR/ΔX、ΔVSWR、位置偏差与数据来源 |
| 7 | 验证报告 | 报告已写入校准库 `validation` 组，可在该页查看原始 JSON 或另存 |

**判读**：`|ΔΓ| ≤ 容差` 且 `位置最大偏差 ≈ 0` 才算到位且阻抗达标；
若位置到位但 `|ΔΓ|` 偏大，参考 §6 与 11-08 记录的 A→B→A 回程偏移
（探针落座 / Z 轴回差导致的方向相关系统性偏差），先用「验证报告」页的
重复性验证量化，而不是直接改容差。

**0.3.8 及更早**：只能在「阻抗调谐」页手输 R/X → 搜索候选 → 移动 → 实测验证，
且实测结果只有 Γ 与 `|ΔΓ|`；Smith 图不能点选，界面上没有 VSWR。
