# 0.5.13.7 维护更新（建库 / 派生 / Smith / 轴初始化）

> 日期：2026-11-21　分支：`feature/0.5.13-move-only`
> 本版修复操作现场反馈的 6 个问题，均不改变已保存校准库的数据格式。

---

## 1. 首次建库报「载入失败：load a calibration database first」

**现象**：第一次点「初始化并建立校准库」弹出载入失败；第二次再点就好了。

**根因**：首次建库只调用 `manager.prepare()` 写出 HDF5 文件头，没有把库加载进内存，
`state.studio['data']` 仍为 `None`。但建库完成广播会通知所有校准页，矢量重复性页随即去读点位，
抛 `RuntimeError`，被它自己的 `except` 捕获后弹出「载入失败」。第二次因文件已存在走"续扫"分支，
会调用 `_load_database()` 填充 `data`，所以不再报错。

**修复**：`studio_setup()` 在两种分支下都调用 `_load_database(..., keep_task=True)`，
首次建库后立即把（尚为空的）库载入内存；`studio_library_points()` 对"已建立但为空"的库返回
空点位列表而不是抛错。现在首次建库干净完成，不再有误导性的报错弹窗。

## 2. 派生新库需要先选频率点

宽频库原先派生时会把**全部频率 × 全部点位**都写进新库，点数爆炸、难以查看。

- 桌面「按 Γ 分布派生新库」与 Web 控制台均新增**频率下拉**，选项来自当前库的频率列表（GHz 显示），派生前必须选定。
- `derive_by_gamma_plan()` 在指定频率时，新库只写该频点的 S 参数（数据从 `P×F` 降为 `P×1`），并在元数据中记录 `frequency_list` 与 `plan_frequency_hz`。
- 不指定频率时保持旧的"全频段派生"行为（兼容既有脚本/测试）。
- 「按频率切分」派生现在尊重其"频点索引"输入，可只导出选中的那一个频点，不再一次生成一堆库。

## 3. Smith 图的频率按库中频率列表选择

矢量重复性页与 Γ 派生页的 Smith 图新增**频率下拉**，条目由 `studio_library_points()` 返回的
`frequencies_hz` 填充（GHz 显示，内部 Hz）。切换频率会按该频点重新计算每个点的 |Γ| 并重绘。

## 4. 矢量重复性校验必须先选频率

**桌面与 Web 均把频率改为必选**：未选择时点击「开始矢量重复性测试」会提示先选频率，不会启动。
启动时把 `frequency_hz` 传给后端；`studio_vector_repeatability()` 只比较所选频点的 S11，
报告 `frequency_hz` 只含该频点并带 `single_frequency: true`，避免整频段的海量行淹没结果。
不选频率的旧调用仍走全频段（向后兼容）。

## 5. Smith 图点选 + 缩放 / 平移 / 复原

- 矢量重复性页的 Smith 图接上了 `picked` 信号：**单击图上的点**会选中表格里最近的点位（|ΔΓ| 阈值 0.25）。
- 两处 Smith 图（矢量重复性、Γ 派生）都加了控制行：**缩放 / 移动模式切换、放大、缩小、复位**；
  同时支持滚轮缩放、拖拽平移、双击/复位恢复原视图。
- Web 控制台的两块 Smith canvas 也补齐了放大/缩小/复原按钮与滚轮缩放、拖拽平移；矢量重复性 canvas 支持点击选点。

## 6. 移动控制：单轴初始化 + 一键初始化

"初始化"定义为**回零 + 反馈位置 MPOS 手动设为 0**（与仅回零不同，初始化同时归零机械坐标与编码器读数）。

- 后端 `ZmotionController` 新增 `set_mpos()`（底层 DLL 早已绑定，之前未封装到 link 层）。
- 每个轴的面板新增「初始化」按钮；全局操作区新增「一键初始化全部轴」（会弹确认框，机械会移动）。
- 一键初始化复用各页面已有的回零路径（真机走 OP 脉冲、虚拟走 DATUM），并**保证 X 轴最后初始化**
  （耦合机型须先给探针轴建立参考）。初始化按钮在运动执行期间会被禁用，与其余运动控件一致。
- Web 控制台新增 `/api/hardware/initialize`、`/api/hardware/initialize_all` 两个接口及对应按钮。
- 虚拟控制器没有 MPOS 寄存器，初始化退化为仅回零，不会报错。
